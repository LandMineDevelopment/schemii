04

Tables, Views, and SQL workspaces

Use the shared selector and left tool rail without changing the saved target. Views opens on verified lineage; Browse opens the searchable ordinary/materialized-view catalog on the right. Sources feed query-local SQL stages, including the required outer-SELECT root, before the final view and any downstream relation consumers. Edit the separate PostgreSQL definition pane and use Preview changes before create, replace, recreate, or delete.

  • Standalone SQL keeps browser-local query views in the Query menu. Its header shows the exact profile, database, and namespace; distinct rail actions run the current statement or full script. Read-only is the default, write mode is query-local, and Stop appears only while PostgreSQL is running.
  • Editor and Results exchange vertical space. Diagnostics stay in their error result; Load more, Export JSON, and Close result act on an incomplete retained result without replay. The separate shared Console offers Managed read, all-or-nothing, explicit transaction, and autocommit/maintenance modes; PostgreSQL role permissions remain authoritative.

PostgreSQL stays authoritative

Save and test the shared profile, then verify the exact database and namespace; system namespaces are an explicit option. Import / Refresh updates the design from live PostgreSQL, while Preview / Apply reviews SQL, warnings, locks, blockers, and destructive opt-ins in the other direction.

  • Re-preview after the design, profile, or live catalog changes. If an outcome is unknown, reconcile it instead of blindly replaying.
  • PostgreSQL may commit before local saved-design synchronization reports success; the result reports those outcomes separately.

07

Save, move, and recover safely

The graphical New, Open, Save, Upload SQL, and Download design controls manage saved files. SQL upload creates a new saved design; JSON and SQL downloads are one-way local copies. Restore examples lives under Help. Autosave reports Saved to file for tables, relationships, functions, views, schema objects, and layout.

  • Database drift can be refreshed or dismissed. A semantic PostgreSQL refresh preserves established positions, colors, and per-layer viewports.
  • A stale schema or layout conflict freezes autosave: Export local edits, then explicitly Refresh saved design. Open Help to replay this guide.
