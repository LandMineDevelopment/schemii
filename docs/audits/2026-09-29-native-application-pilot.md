# Native application pilot and cleanup observations

The authenticated two-account native pilot established bounded Schemii
application acceptance beyond the earlier twelve-connection mechanical probe.
It did not establish full manual UI acceptance or justify retiring the legacy
execution layer. The tested deployment was frozen at `507ebfe`, verified through
the supported launcher and canonical local/Tailscale HTTPS origins.

The coordinator used two native `ui_tester` children and a separate
`qa_reviewer` lane. Each lane was prepared and dispatched through `./test.sh`,
claimed to the actual returned native thread identity before actions, and bound
to that thread's own `schemii_browser` connection. Ordinary preview tabs were
not cookie-isolation evidence. Configuration checks reported thirteen total
slots, trusted cooperative guards and no hook-loading errors; those observations
did not themselves establish application acceptance.

## Observed workflows

Both testers visibly authenticated to their assigned retained accounts. Two-way
logout checks observed one account signing out while the other remained signed
in, then restored the original account. Owned local designs were created with
three typed columns, saved, reloaded and switched; exact revisions and persisted
rename state were checked. Blank-name validation preserved the existing saved
state. Mobile saved-state readback used a 390 by 844 viewport.

The pilot downloaded actual JSON and SQL files, respectively 1,787 and 375 bytes,
with typed content/hash receipts rather than relying on a download notification.
Seven case results received bounded independent acceptance. Test execution,
visual review and cleanup status remained separate; a completed worker turn
was not treated as a passing product case.

Four file cases remained blocked. There was no supported JSON design-upload
control, and the tested SQL Upload prerequisite was unavailable. The pilot did
not substitute JSON content into a SQL chooser or invent an upload capability.

The pilot exposed loading Fit behavior: an unavailable live catalog displayed
misleading empty-table guidance, and the desired table could remain clipped with
the inspector open. Stable ready-state Fit worked. The reviewed readiness change
in [PR #152](https://github.com/LandMineDevelopment/schemii/pull/152) still needs
live native verification on its rebuilt source.

Capture validation also rejected legitimate owned workspace selection URLs.
[PR #151](https://github.com/LandMineDevelopment/schemii/pull/151) fixes that
bounded route contract. Eight normalized inspector attestations were withdrawn;
that later source change does not retroactively accept their images. The pilot
therefore does not claim complete inspector/geometry acceptance.

## Actual lifecycle and automatic cleanup

Closing a browser context and stopping its extension transport were observed
separately. The native interface did not expose a supported thread/session-close
or MCP-reload control. Completed and interrupted native turns retained transport
connections; an interruption/follow-up experiment confirmed a connection remained
usable. `browser_close` alone did not remove the connection-owned output.

After the pilot owners signed out and closed their browser contexts, supported
`native-release` terminated only each bound, identity-validated extension
supervisor. All three owned supervisor/child/guardian identities and disposable
output directories disappeared. A live peer remained usable during the first
two releases. This establishes owned extension shutdown, not native thread
closure.

Harness cleanup released the pilot account reservations and deployment lease.
Scoped application fixture cleanup initially refused the still-live controller;
after its observed exit, the supported sweep removed seven recorded owned
workspaces with zero pending creations. A repeated sweep removed zero. Retained
accounts, credentials, reader fixtures, profiles and unrelated sessions remained.

Separate controlled browser lifecycle evidence observed real output expiry after
629.10 seconds and the documented 20 MiB soft budget: older output was evicted,
while the current response could temporarily exceed the budget. Normal shutdown,
an ignoring child, forced supervisor/app-server termination and orphan recovery
left zero owned process entries, including zombies, and disposable directories,
while preserving a separate live peer. No manual deletion established these
automatic cleanup results. The detailed limits and evidence are retained in
[the browser cleanup report](2026-09-29-native-cleanup-validation.md).

Selected pilot evidence was exported before temporary output expiry/shutdown:
72 files totaling 5,800,624 bytes, with path/size/hash receipts, remain in a private
audit archive outside disposable worktrees. Controller/session files, credentials
and unselected browser output are not public report evidence. An early worktree
removal also removed untracked receipt copies; exact receipts were recovered from
retained immutable tool output and their recovery provenance recorded. That
recovery does not replace the observed automatic runtime cleanup checks.

## Remaining acceptance

The next plan uses ten native testers and a separate reviewer, exact existing
reader/writer grants, typed upload/download oracles and one controlled persisted
write interruption/recovery. It is not yet a prepared or accepted run. The user
selected `gpt-6-luna` with high reasoning effort for its native UI agents.

Current prerequisites are reviewed console/lifecycle source, exact writer fixture
ownership, live grant checks and a rebuilt leased deployment verified at both
HTTPS origins. Recovery must preserve completed results and reconcile saved state
before replaying a write. Unknown ownership remains blocked rather than adopted.

Full application acceptance, larger concurrent workflows, upload/COPY capability,
broader reports/paid streaming, forced application fixture cleanup parity and
legacy retirement remain open in
[the native workflow rollup](https://github.com/LandMineDevelopment/schemii/issues/137)
and [manual acceptance issue #73](https://github.com/LandMineDevelopment/schemii/issues/73).
This pilot establishes neither server capacity nor simultaneous model inference.
